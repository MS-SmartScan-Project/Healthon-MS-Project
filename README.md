# MS SmartScan — موقع العرض (هيلثون)

موقع يعرض فكرة الجهاز، ويشغّل نموذج الذكاء الاصطناعي `best.pt` مباشرة على صور الرنين المغناطيسي.
**بدون PHP وبدون XAMPP وبدون MySQL**، ويحتاج بايثون فقط.

## التشغيل

| الجهاز | الطريقة |
|---|---|
| **ويندوز** | دبل كليك على **`START-Windows.bat`** |
| **Raspberry Pi** | دبل كليك على **`start-raspberry.sh`** ثم **Execute** (أو اكتبي في الطرفية `./start-raspberry.sh`) |

وبس ✅
- **أول مرة فقط:** ثبّتي الاعتماديات بالأمر `python -m pip install -r requirements.txt`.
- **بعدها:** يفتح المتصفح لحاله على **http://localhost:8000**.
- انتظري لين تصير الشارة فوق 🟢 **النموذج جاهز**.
- **لإيقاف الموقع:** سكّري النافذة السوداء.

الشيء الوحيد اللي لازم يكون مثبّت هو **Python**. إذا مو موجود، ملف التشغيل يفتح لك صفحة تنزيله.

## طريقة الفحص (الواجهة بالإنجليزية)
1. في قسم **Workspace** اكتبي **Patient name** و **Medical number** — الاثنين **إلزاميين**.
2. اختاري **Upload** (رفع صورة) أو **Camera** (ثم Start camera).
3. اضغطي **Run AI analysis** (أو **Capture & analyze** مع الكاميرا).
4. تظهر النتيجة مع نسبة الثقة، والخطوة السريرية التالية (تحليل CSF: OCBs و κ-FLC) عند وجود آفة مشتبهة.
5. يُحفظ الفحص تلقائياً في **Patient Records** (بحث، فلترة، تصدير CSV).

### قواعد البيانات الجديدة
- **الرقم الطبي هو المعرّف الفريد للمريض** (جدول `patients`). إذا كُتب رقم مسجّل باسم مختلف يُرفض الفحص.
- **منع تكرار صورة الرنين:** نفس الصورة (نفس البايتات أو نفس البكسلات) لا يمكن ربطها بمريض آخر.
  تُحفظ بصمتان SHA-256 (`source_sha256` و `pixel_sha256`)، ولا يُحذف أو يُعدَّل سجل المريض الأصلي.
  إعادة رفع نفس الصورة لنفس المريض مسموحة.
- عند أول تشغيل تُنشأ الأعمدة والجداول الجديدة تلقائياً دون حذف أي سجل قديم، ويُنشأ سجل مريض لكل فحص قديم فيه اسم ورقم.

## الملفات
| الملف | الوظيفة |
|---|---|
| `server.py` | السيرفر: يعرض الموقع، ويستقبل الصور، ويحفظ السجل |
| `detector.py` | يحمّل `best.pt` مرة وحدة، ويحلل بنفس خطوات `predict.py` |
| `best.pt` | نموذج YOLO11n المدرَّب (100 epoch، 640px — Precision 99.1%، Recall 97.2%، mAP50 99.2% على بيانات التحقق) |
| `static/assets/logo.webp` | الشعار الرسمي كما هو دون تعديل |
| `predict.py` | أداة سطر أوامر مستقلة لاختبار صورة دون تعديل الملف الأصلي |
| `START-Windows.bat` · `start-raspberry.sh` | ملفات التشغيل |
| `static/` | الواجهة: `index.html` و`style.css` و`app.js` |
| `data/` | يُنشأ تلقائياً: قاعدة SQLite والصور |

## كيف يحلل الموقع الصورة؟
نفس خطوات `predict.py` بالضبط:
1. تحويل الصورة للرمادي وتحسين التباين بخوارزمية **CLAHE** (clipLimit=3.0, tile 8×8).
2. تشغيل `best.pt` بحد ثقة `conf=0.05`.
3. **إذا وُجدت بؤر:** النتيجة `Infected` مع أعلى نسبة ثقة. **وإلا:** النتيجة `Healthy` دون اختلاق نسبة ثقة للسلامة.

نتيجة `Infected` بثقة أقل من **70%** تُعرض **غير حاسمة** ولا تُحوّل إلى سليمة. يمكن تغيير الحد من `MIN_CONFIDENCE` في `server.py` بعد تقييمه على بيانات تحقق مستقلة.

## الخصوصية والأمان

- السيرفر يستمع إلى `localhost` فقط ولا يعرّض بيانات المرضى للشبكة.
- الصور والسجل محفوظان محلياً داخل `data/` ولا ينبغي رفع هذا المجلد إلى Git.
- طلبات التحليل والحذف محمية برمز CSRF، مع تحديد معدل الطلبات والتحقق من الصور.
- هذه أداة مساعدة وليست تشخيصاً طبياً مستقلاً.

## حل المشاكل
- **الشارة حمراء «Model unavailable»:** ثبّتي `requirements.txt` وتحققي من وجود `best.pt` ثم أعيدي التشغيل.
- **الكاميرا ما تشتغل:** افتحي الموقع على `localhost` واسمحي للمتصفح باستخدام الكاميرا، أو استخدمي «رفع صورة».
- **المنفذ 8000 مشغول:** السيرفر يجرب 8001 و8002… تلقائياً، والرابط يطلع لك في الطرفية.
